## Reconciliation and reload contract

A server-only ephemeral receipt cannot prove exactly-once across crashes. The UI must retain enough bounded recovery metadata without raw holdings values before submitting a write, without persisting the token, file, tickers, notes or values.

- One per-tab sessionStorage marker (its digests are fingerprints derived from financial content):version,portfolioid,rawinput digest,normalized digest,reviewed row numbers (max200),and state uncertain/saved. Write and read it back BEFORE confirmation. If storage is unavailable/malformed or an unresolved marker belongs to another portfolio, keep preview read-only and block another confirmation. Marker is bounded; never evict uncertainty silently. No auto-retry on reload, timeout, process restart or lost response.
- Keep the chosen File/preview values only in memory. On lost response/unknown token/commit ambiguity/cancel during confirmation, show Outcome needs reconciliation, no retry sent. Reload/portfolio switch restores the marker warning; a token is never reconstructed. Selecting a file in recovery mode compares the original reviewed CSV rather than creating a fresh executable preview.
- New read-only POST `/holdings/reconcile` accepts bounded CSV plus bounded form manifest (portfolio,digests,unique reviewed row numbers). Verify raw file digest, strict local parse, rebuild selected normalized persisted fields through existing row mapper/schema, verify canonical proposal digest; no quote-provider/AI call and no DB writes. This is comparison, not authoritative ticker validation or proof of authorship. Under generation guard snapshot current selected active holdings and compare EVERY reviewed field. Return matching/mismatching rows (absent is a known mismatch), full expected/current values, and counts. Corrupt/nonfinite or duplicate active stored records are unknown rows rather than coerced zero or a chosen first match. Failed read/generation/invalid metadata stays unknown and does not unlock a fresh preview.
- Verified pre-write busy/stale/expired responses carry saved=false/not_executed=true plus matching portfolio,digest,reviewed row numbers. Only after validating that context may the UI clear the prewritten recovery marker: busy retains the in-memory live preview for one explicit manual retry; stale/expired revokes it and permits a new explicit preview. Reload after either has no write marker/token and never retries. Unknown/malformed/context-mismatched responses retain recovery blocking.
- Render bounded25row comparison pages as text with expected/current ticker,shares,cost,watchlist,class,notes,cadence. Explicitly state matching records do not prove this request created them. Only after a successful known comparison AND a user acknowledgement of inspecting it may Start a fresh preview clear the marker. That action clears recovery UI; the user separately chooses/reviews/confirms another file. Never automatically import, undo successful rows, or restore a database. Mismatch remains explained and requires that explicit acknowledgement/action; unknown remains blocked.
