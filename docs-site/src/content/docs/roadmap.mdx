The previous roadmap named target weights, a trade export, and a what-if simulator. Those
ideas shipped together in **v5.11.0** as a deliberately bounded Plan & Protect workflow.
**v5.12.0** then tightened the real keyboard and compact-screen journeys around that work.
This page records outcomes instead of leaving shipped work labelled as future work.

## Recently shipped

<CardGrid>
	<Card title="Closed means closed" icon="check-circle">
		Closed header details are inert as well as invisible, and Escape restores focus to
		the trigger that opened them.
		<br /><br />**Status:** shipped in v5.12.0
	</Card>
	<Card title="Phone-width calm" icon="mobile">
		Senpai stays below financial content, while Plan cards fit 320 px and keep wide
		tables in local scrollers.
		<br /><br />**Status:** shipped in v5.12.0
	</Card>
	<Card title="Context-bound review" icon="warning">
		Restore confirmation consumes Escape first, and edited rehearsal inputs invalidate
		both the visible preview and any late response.
		<br /><br />**Status:** shipped in v5.12.0
	</Card>
	<Card title="Target weights & drift" icon="random">
		Set a complete integer-basis-point course over owned eligible holdings, then compare
		target and actual allocation only when every required USD quote is usable.
		<br /><br />**Status:** shipped in v5.11.0
	</Card>
	<Card title="Annual realized recap" icon="document">
		Export one calendar year of stored sales with an average-cost-basis recap. It is a
		bookkeeping record, not tax-lot or tax-filing software.
		<br /><br />**Status:** shipped in v5.11.0
	</Card>
	<Card title="Buy rehearsal" icon="random">
		Preview an external-cash USD buy for a ticker already held. It writes nothing,
		does not trim, does not forecast, and is not a recommendation.
		<br /><br />**Status:** shipped in v5.11.0
	</Card>
</CardGrid>

<SenpaiTip>

	records ZIP, manual-backup freshness, and opt-in daily automatic backup.
</SenpaiTip>

## What comes next

There is no dated public promise for the next feature. Proposed work is discussed in GitHub
issues and becomes a shipped claim only after the implementation, tests, packaged app, and
release artifacts agree.

<Aside type="tip" title="Got a feature you'd fight for?">
	The list grows from real requests. [Open an
	issue](https://github.com/udhawan97/FolioOrb/issues/new) with your use case — Senpai
	reads every one and has opinions about most.
</Aside>
